# H3RndNew 界面与功能分离（round-21）

参考蓝本：H3BattleStore `docs/09-界面与功能分离.md`（`IBattleStoreUi` 契约 + `g_uiPort` 分发）；同族实施：H3Auto `docs/13-界面与功能分离.md`。本文记录 H3RndNew 的对应改造：四个界面全部经契约（`modules/UiPort.hpp`）驱动，钩子层只做翻译与铠甲，界面实现可整套替换。

## 目标 / 非目标

**目标**
- 界面（像素、控件、手势、命中、开窗时序）与功能（模型、持久化、判定、钩子）分离，以后换界面只动实现文件与接线。
- 逐像素不变：本轮是**代码搬移**，不是改版；游戏内行为由用户上机验收。

**非目标**
- 不做多界面运行期切换（单实现直连；将来需要时按 H3BattleStore `UiPortDispatch_` 模式加分发器）。
- 不动模型语义、钩子地址、存档格式、任何功能行为。

## 判定口径（与 H3BattleStore 一致）

> 换一套界面后仍然成立的是功能；换界面就没了的是界面。

- 功能：`g_true_random` / `g_bank_maximize` / `g_bank_ratio` / `g_settings_hotkey_scan` 模型、INI 持久化、RNG 替换判定、窗口状态机、奖励后处理、仓库存取事务。
- 界面：复选框/滑块/百分比/标签控件、五按钮、分页、面板绘制与命中、设置窗控件树、改键侦听交互。
- 共享（不算界面）：日志文案、`SmallFontHeight_` / `FontTextHeight_` 布局助手、GBK 转换 `Utf8ToGbk_`、键名 `ScanToName_`。

## 四个界面与契约

契约头 `modules/UiPort.hpp`（无 H3API 依赖，只前向声明 `h3::` 类型，参数类型全限定 `h3::`——测试 TU 不 `using namespace h3` 也能编译）：

| 祑口 | 事件源（钩子层） | 方法 | 理由 |
|---|---|---|---|
| `IScenarioUi` | TrueRandom 的选图构造/消息钩子 | `DialogCreated` / `DialogMessage` / `DialogMessageDone` | 构造后清残留+清单日志；消息前吞自家控件；消息后关窗清理/首消息摆控件/可见性 |
| `ISettingsUi` | SettingsDialog 的键盘钩子 0x4EC1C0 | `KeyMsg(keyDown, scan, autoRepeat)` | 开窗、改键侦听、运行中吞键；WM 参数已由钩子层翻译 |
| `IWarehouseUi` | WarehouseUiStageB 两只 modal LoHook + dlg+0x70 回调 | `Attach` / `Detach` / `Callback` | attach 传 dlg/hero/背包容器矩形；detach 传 dlg；Callback 携带 SEH 铠甲与「原生 callback 恰好一次」约定 |

接线：`modules/UiPortWiring.inc.cpp` 在全部实现之后、Entry 之前定义
`IScenarioUi* g_uiScenario = &g_hdScenarioUi;` 等三个指针。单 TU 静态初始化按定义顺序：实现对象先构造、指针后赋值；运行期（DllMain 起的任何钩子回调）恒非空，钩子层不判空（trampoline 里留一个防御性空判，仅日志层面的兜底）。

## 踩坑记录（本轮实际遇到）

- **GUARD 注册位置**：`GuardRegisterHook_` 静态注册必须在文本上先于使用。`GUARD_WH_UI_MODAL` 在面板代码（Panel L190 `__except`）里被引用，而注册被我挪到了钩子文件——C2065。修正：三只 warehouse GUARD 都注册在 Panel 顶部（同一未命名命名空间，定义先于 StageB 钩子文件），StageB 直接使用不再注册（避免二次注册占 id 槽）。
- **契约类型限定**：接口参数若用裸 `H3SelectScenarioDialog`，测试 TU（不 `using namespace h3`）编不过。修正：契约头内全部 `h3::` 全限定；实现文件在 `using namespace h3;` 的生产 TU 里裸名仍匹配 override。
- **.NET 静态方法不跟 PowerShell 位置**：`[IO.File]::ReadAllLines` 用进程 CWD，`cd` 不生效——拆文件脚本必须绝对路径。
- **SEH/展开互斥**：`HdWarehouseUi::Callback` 带 `__try`，方法内只放 POD 局部（沿用原函数写法）；`OnKeyMsg_` 的 `handled` 在 `__try` 外聚合。

## 换界面怎么做（将来）

1. 新实现三个接口（或只换其中之一），自带控件 id/布局/命中；不回调钩子层。
2. `UiPortWiring.inc.cpp` 指向新实现；契约不变则功能层与钩子层零改动。
3. 两套并存时可参考 H3BattleStore `UiPortDispatch_`：运行期按配置在两个实现间分发，分发器实现「未配置时指向默认实现」的兜底。
